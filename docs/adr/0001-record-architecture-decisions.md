# 1. Record architecture decisions

**Date:** 2026-10-13
**Status:** Accepted

## Context

I want to keep track of *why* I made each important technical choice, so I can explain it later and revisit it if the context changes.

## Decision

I will record significant decisions as short Architecture Decision Records (ADRs) in `docs/adr/`, numbered in order, using this template:

- **Context**: the problem and constraints
- **Decision**: what I chose
- **Consequences**: what gets easier, what gets harder

## Consequences

Documentation lives next to the code and is versioned with it ("documentation as code").
